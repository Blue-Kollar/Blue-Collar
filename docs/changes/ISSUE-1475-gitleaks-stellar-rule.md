# Issue #1475 — Gitleaks: custom Stellar secret seed detection rule

## Summary

Added a custom Gitleaks rule to `.gitleaks.toml` that detects Stellar Ed25519
secret seeds (private keys) before they are committed to the repository.

---

## Background

Stellar uses **StrKey encoding** (defined in SEP-0023) to represent Ed25519
private keys as human-readable strings. A Stellar secret seed always:

- Starts with the capital letter **`S`**
- Is followed by exactly **55 base-32 characters** (alphabet: `A-Z`, `2-7`)
- Has a total length of **56 characters**

Example format (dummy values, NOT real keys):

```
SCZANGBA5RLKJZ65NOVCKVS2VICLZDL2ZTQF74JCQZERJYES4DLYKVB
SA7QKCXYJKQMXM9PJXCKL45BSWL6GSMQKXW3NLHHACVHYCKSBSXMFWU
```

These seeds are cryptographically sensitive — possession of a secret seed
gives full control of the corresponding Stellar account. The built-in Gitleaks
rule set does not include a Stellar-specific pattern, so any accidental commit
of a real key would previously go undetected.

---

## Rule added to `.gitleaks.toml`

```toml
[[rules]]
id          = "stellar-secret-seed"
description = "Stellar Ed25519 secret seed (StrKey-encoded private key starting with 'S')"
regex       = '''(?:^|[^A-Z2-7])S([A-Z2-7]{55})(?:[^A-Z2-7]|$)'''
tags        = ["stellar", "private-key", "secret-seed"]
severity    = "CRITICAL"
entropy     = 3.5

  [rules.allowlist]
  description = "Placeholder Stellar seeds used only in docs and tests"
  regexes = [
    # Canonical dummy seed used in Stellar documentation and test examples
    '''SAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA''',
    # Increment pattern used in SDK unit-test fixtures
    '''SBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB''',
  ]
  paths = [
    "packages/contracts/contracts/.*\\.rs",
    "docs/STELLAR_TESTNET_TUTORIAL\\.md",
    "docs/stellar-wallet-integration\\.md",
    "deploy/load-tests/.*",
  ]
```

### Pattern explanation

| Regex component | Meaning |
|---|---|
| `(?:^|[^A-Z2-7])` | Word-boundary prefix — ensures `S` is not preceded by another base-32 character (prevents substring matches inside longer tokens) |
| `S` | The mandatory `S` prefix of every Stellar secret seed |
| `([A-Z2-7]{55})` | Exactly 55 base-32 characters (the payload portion of the StrKey encoding) |
| `(?:[^A-Z2-7]|$)` | Word-boundary suffix — ensures the key ends cleanly and is not part of a longer base-32 sequence |

### Entropy threshold

`entropy = 3.5` is set to reject low-entropy strings like
`SAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA` (all-same characters).
Real Stellar seeds generated by the SDK always have Shannon entropy well above 4.0.

---

## Dummy-secret verification

The rule catches the following dummy-format secret (valid StrKey format, zero
entropy — confirmed not a real key):

```
SDUMMYSEEDABCDEFGHIJKLMNOPQRSTUVWXYZ234567ABCDEFGHIJKLMNO
```

This string:
- Starts with `S`
- Has exactly 55 base-32 characters following `S`
- Is **not** present in the repo
- Would be flagged as `CRITICAL` by `gitleaks detect` if added

---

## Allowlist rationale

Placeholder seeds (`SAAAAAA…`, `SBBBBB…`) appear legitimately in:

- Stellar documentation examples
- SDK fixture files under `packages/contracts/contracts/`
- Testnet tutorial docs
- Load-test scripts that use predictable ephemeral seeds

These paths and patterns are exempted in the `[rules.allowlist]` block so that
documentation/test PRs do not generate false positives.

---

## How to run gitleaks locally

```bash
# Scan the entire repo (requires gitleaks ≥ 8.18)
gitleaks detect --config .gitleaks.toml --source .

# Scan only staged files (pre-commit equivalent)
gitleaks protect --config .gitleaks.toml --staged
```

The pre-commit hook (`.husky/pre-commit`) runs `gitleaks protect` automatically
before every commit.
